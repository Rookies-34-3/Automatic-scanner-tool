# ROOKIESCAN 보고서 설계

## 1. 보고서 원칙

보고서의 기준 데이터는 `ScanReport` JSON이다. Streamlit 화면과 HTML 보고서는 이
JSON을 표현하는 출력 형식으로 본다. 자동 생성 설명이 추가되더라도 판정, 증거,
요청·응답 정보는 스캐너가 만든 구조화 데이터에서 가져온다.

비밀번호, 세션 쿠키, Authorization 헤더, API 키는 보고서에 저장하지 않는다.
요청·응답 본문은 필요한 근거만 남기고 토큰과 개인정보를 마스킹한다.

## 2. 보고서 구성

### A. 표지와 기본 정보

- 보고서 ID와 스캔 ID
- 대상 이름과 기준 URL
- 점검 시작·종료 시각
- 실행한 모듈
- 점검 권한 확인 문구
- 보고서 생성 버전

### B. 요약

- 전체 검사 수
- `VULNERABLE`, `REVIEW`, `PASS`, `INFO`, `ERROR`, `SKIPPED` 수
- 심각도별 취약점 수
- 가장 높은 심각도
- 실행 성공·실패 모듈 수

### C. 점검 범위

- 허용된 URL과 경로
- 검사한 엔드포인트 수
- 선택한 모듈과 실제 실행한 모듈
- 제외한 범위와 사유
- 인증 프로필 이름 또는 참조 ID

### D. 주요 발견 결과

`VULNERABLE`과 `REVIEW`만 심각도 순으로 먼저 표시한다. 같은 심각도에서는 신뢰도가
높은 결과를 먼저 표시한다.

| 필드 | 설명 |
|---|---|
| ID | 보고서 내 고유 Finding ID |
| 제목 | 사람이 빠르게 이해할 수 있는 취약점명 |
| 모듈 | 결과를 만든 스캐너 ID |
| 판정 | `VULNERABLE` 또는 `REVIEW` |
| 심각도 | `CRITICAL`부터 `INFO`까지 |
| 신뢰도 | `HIGH`, `MEDIUM`, `LOW` |
| 위치 | URL, HTTP 메서드, 파라미터명과 위치 |
| 근거 | 상태 코드, 반응 차이, 탐지 문자열 등 핵심 증거 |
| 영향 | 공격 성공 시 가능한 영향 |
| 재현 절차 | 승인된 환경에서 확인할 최소 단계 |
| 조치 방법 | 수정 방향과 검증 방법 |
| 분류 | CWE와 OWASP 분류 |

### E. 상세 결과

각 Finding은 다음 순서로 표현한다.

1. 제목, 판정, 심각도, 신뢰도
2. 대상 엔드포인트와 파라미터
3. 탐지 근거
4. 영향
5. 재현 절차
6. 권장 조치
7. 요청·응답 요약
8. 모듈 원본 세부 정보

민감한 페이로드나 응답은 기본 화면에서 접고, 보고서 설정에서 증거 포함을 선택했을
때만 마스킹된 형태로 내보낸다.

### F. 점검 커버리지

취약점이 발견되지 않은 항목도 검사 여부를 확인할 수 있게 기록한다.

- 모듈별 검사 엔드포인트 수
- `PASS` 목록
- `SKIPPED` 목록과 사유
- `ERROR` 목록과 오류 단계
- 미실행 모듈과 미실행 사유

### G. 부록

- AI 라우팅 결정: Sink ID, 선택 모듈, 선택 이유
- 모듈 실행 시간과 버전
- 적용한 제한 시간과 옵션
- 마스킹된 원본 JSON 다운로드

## 3. Streamlit 결과 화면

한 화면에서 다음 순서로 보여준다.

```text
[대상 / 스캔 상태 / 완료 시각]

[Critical] [High] [Medium] [Low] [Review]

[필터: 모듈 | 판정 | 심각도 | 엔드포인트]

[주요 발견 결과 표]
  └─ 행 선택 시 상세 결과 펼침

[점검 커버리지]
[오류 및 건너뜀]

[JSON 다운로드] [HTML 다운로드]
```

진행 중에는 모듈별 상태를 `대기`, `실행 중`, `완료`, `오류`로 표시한다. 완료 전에는
부분 결과를 최종 보고서로 표시하지 않고 진행 로그 영역에만 보여준다.

## 4. 출력 형식

초기 출력은 두 가지로 제한한다.

- JSON: 다른 시스템 연동과 재처리를 위한 기준 데이터
- HTML: 브라우저에서 읽고 공유하기 위한 보고서

PDF가 필요하면 HTML 출력이 안정된 뒤 같은 `ScanReport`를 입력으로 추가한다.

## 5. 보고서 생성 함수 경계

구현 시 보고서 모듈은 다음 경계만 가진다.

```text
build_report(scan_request, module_results) -> ScanReport
render_json(scan_report) -> bytes
render_html(scan_report) -> bytes
```

렌더러는 취약점 재판정이나 심각도 변경을 하지 않는다. 판정 정규화는 보고서 빌더에
들어오기 전에 끝낸다.
